The code separates the client into five jobs:

```
main()
 ├── client_parseopt()
 ├── connect_to_server()
 ├── run_client_protocol()
 │    └── send_initialization()
 │         └── send_all()
 ├── close()
 └── free()
```

This separation matters because each function handles one level of responsibility.

## 1. `main`

```
int main(int argc, char *argv[]) {
    struct client_arguments args;

    if (client_parseopt(argc, argv, &args) != 0) {
        return 1;
    }

    int socket_fd = connect_to_server(&args);

    if (socket_fd < 0) {
        free(args.filename);
        return 1;
    }

    if (run_client_protocol(socket_fd, &args) != 0) {
        close(socket_fd);
        free(args.filename);
        return 1;
    }

    close(socket_fd);
    free(args.filename);
    return 0;
}
```

`main()` coordinates the whole program. It does not need to know the details of sockets or individual protocol messages.

### `argc` and `argv`

```
int argc
char *argv[]
```

These contain the command-line arguments.

For:

```
./client -a 127.0.0.1 -p 41714
```

they roughly contain:

```
argc = 5

argv[0] = "./client"
argv[1] = "-a"
argv[2] = "127.0.0.1"
argv[3] = "-p"
argv[4] = "41714"
```

### Creating `args`

```
struct client_arguments args;
```

This creates the actual structure that will store all parsed options.

```
client_parseopt(argc, argv, &args)
```

passes the address of that structure. The parser can therefore modify the original `args`.

### Return-value checks

```
if (client_parseopt(...) != 0)
```

The convention we are using is:

```
0     = success
nonzero = failure
```

For `connect_to_server()`, the convention differs because it returns a socket descriptor:

```
0 or greater = socket descriptor
-1           = failure
```

### Cleanup

```
close(socket_fd);
free(args.filename);
```

Two different resources must be released:

- `close()` releases the operating-system socket.
- `free()` releases memory previously allocated by `malloc()`.

Every successful `socket()` should eventually have a `close()`. Every successful `malloc()` should eventually have a `free()`.

## 2. `connect_to_server`

```
int connect_to_server(const struct client_arguments *args) {
    int socket_fd = socket(AF_INET, SOCK_STREAM, 0);

    if (socket_fd < 0) {
        perror("socket");
        return -1;
    }

    struct sockaddr_in server_address;
    memset(&server_address, 0, sizeof(server_address));

    server_address.sin_family = AF_INET;
    server_address.sin_port = htons(args->port);

    int address_result = inet_pton(
        AF_INET,
        args->ip_address,
        &server_address.sin_addr
    );

    if (address_result != 1) {
        fprintf(stderr, "Invalid IPv4 address: %s\n", args->ip_address);
        close(socket_fd);
        return -1;
    }

    if (connect(
            socket_fd,
            (struct sockaddr *)&server_address,
            sizeof(server_address)
        ) < 0) {
        perror("connect");
        close(socket_fd);
        return -1;
    }

    return socket_fd;
}
```

This function performs three operations:

1. Create a TCP socket.
2. Construct the server address.
3. Connect the socket to that address.

### The parameter

```
const struct client_arguments *args
```

Break it apart:

- `struct client_arguments`: the type.
- `*args`: `args` is a pointer to the structure.
- `const`: this function promises not to modify the structure.

Because it is a pointer, fields are accessed with `->`:

```
args->port
args->ip_address
```

That is equivalent to:

```
(*args).port
(*args).ip_address
```

### `socket`

```
int socket_fd = socket(AF_INET, SOCK_STREAM, 0);
```

`socket()` asks the operating system to create a socket.

Its arguments mean:

```
AF_INET      // use IPv4
SOCK_STREAM  // use a reliable byte stream, which means TCP
0            // use the normal protocol for this combination
```

On success, it returns a file descriptor:

```
3
4
5
...
```

A file descriptor is a small integer that identifies an open operating-system resource.

On failure, `socket()` returns `-1`.

### `perror`

```
perror("socket");
```

`perror()` prints your label plus the operating system’s explanation of the latest error.

Possible output:

```
socket: Too many open files
```

The operating system sets a global error value called `errno` when a system call fails. `perror()` translates that value into readable text.

### `sockaddr_in`

```
struct sockaddr_in server_address;
```

This structure represents an IPv4 address and port. Important fields include:

```
server_address.sin_family
server_address.sin_port
server_address.sin_addr
```

Conceptually:

```
server_address
 ├── address family = IPv4
 ├── port = 41714
 └── IP address = 127.0.0.1
```

### `memset`

```
memset(&server_address, 0, sizeof(server_address));
```

`memset()` fills memory with a repeated byte.

Its arguments are:

```
memset(
    destination,
    byte_value,
    number_of_bytes
);
```

Here it means:

```
Start at the address of server_address.
Fill every byte with zero.
Fill exactly the size of the structure.
```

Clearing the entire structure prevents unused fields from containing uninitialized data.

### Address family

```
server_address.sin_family = AF_INET;
```

This records that the structure contains an IPv4 address.

### `htons`

```
server_address.sin_port = htons(args->port);
```

Network protocols use network byte order. Your computer may use a different byte order internally.

`htons` means:

```
host to network short
```

- “host” means your computer’s byte order.
- “network” means network byte order.
- “short” means a 16-bit integer.

TCP and UDP port numbers are 16 bits, so the port uses `htons()`.

For protocol fields that are 32 bits, you use `htonl()` instead.

### `inet_pton`

```
int address_result = inet_pton(
    AF_INET,
    args->ip_address,
    &server_address.sin_addr
);
```

`inet_pton()` converts a human-readable IP address into the binary form required by the socket API.

For example:

```
"127.0.0.1"
```

becomes four binary address bytes.

Its arguments mean:

```
AF_INET                       // input is IPv4
args->ip_address              // input string
&server_address.sin_addr      // output destination
```

Its return values are:

```
1  = valid address converted successfully
0  = input was not a valid address
-1 = address family or system error
```

That is why the code checks:

```
if (address_result != 1)
```

### `connect`

```
connect(
    socket_fd,
    (struct sockaddr *)&server_address,
    sizeof(server_address)
)
```

`connect()` asks the operating system to establish the TCP connection.

Its parameters are:

- The socket descriptor.
- The server’s address.
- The size of the address structure.

The cast:

```
(struct sockaddr *)&server_address
```

is needed because `connect()` accepts a generic address type named `struct sockaddr`. We actually have the more specific IPv4 type `struct sockaddr_in`.

The pointer still points to the same memory. The cast only tells the compiler to treat that memory as the generic address type required by `connect()`.

On success:

```
connect() returns 0
```

On failure:

```
connect() returns -1
```

Common failures include:

- The server is not running.
- The wrong port was provided.
- The IP address is unreachable.
- A firewall blocked the connection.

### Why close on an error?

If `socket()` succeeded but `inet_pton()` or `connect()` failed, the socket still exists. Therefore:

```
close(socket_fd);
return -1;
```

prevents the resource from leaking.

### Successful return

```
return socket_fd;
```

The connected socket descriptor is returned to `main()`. Later functions use it to send and receive bytes.

## 3. `run_client_protocol`

```
int run_client_protocol(
    int socket_fd,
    const struct client_arguments *args
) {
    if (send_initialization(socket_fd, args->hashnum) != 0) {
        return 1;
    }

    /* Next: receive and validate the Acknowledgement. */

    return 0;
}
```

This function manages the assignment-level conversation after the TCP connection exists.

The final version will roughly perform:

```
send Initialization
receive Acknowledgement

repeat N times:
    choose random payload length
    read that many file bytes
    send HashRequest

receive and print N HashResponses
```

Exactly how request sending and response receiving are interleaved can depend on your design, but you must not assume TCP message boundaries.

### Parameters

```
int socket_fd
```

This is copied normally because it is only a small integer.

```
const struct client_arguments *args
```

This gives the function read-only access to the parsed settings.

### Calling `send_initialization`

```
send_initialization(socket_fd, args->hashnum)
```

The Initialization message needs:

- The connected socket.
- The number of HashRequests, `N`.

The function returns zero on success and nonzero on failure.

## 4. `send_initialization`

```
int send_initialization(int socket_fd, int hashnum) {
    uint32_t message[2];

    message[0] = htonl(1);
    message[1] = htonl((uint32_t)hashnum);

    if (send_all(socket_fd, message, sizeof(message)) != 0) {
        return 1;
    }

    return 0;
}
```

The assignment says Initialization is exactly:

```
4-byte Type
4-byte N
```

Therefore, we create two 32-bit integers:

```
uint32_t message[2];
```

`uint32_t` means:

```
an unsigned integer that is exactly 32 bits
```

Since eight bits equal one byte:

```
32 bits = 4 bytes
```

Therefore:

```
message[0] = 4 bytes
message[1] = 4 bytes
total      = 8 bytes
```

### Message type

```
message[0] = htonl(1);
```

The assignment defines Initialization type as `1`.

`htonl` means:

```
host to network long
```

Here, “long” refers to the socket API’s 32-bit conversion operation. It converts a 32-bit value into network byte order.

### Request count

```
message[1] = htonl((uint32_t)hashnum);
```

This converts `N` into network byte order.

The cast:

```
(uint32_t)hashnum
```

converts the regular `int` into the exact 32-bit unsigned type used by the protocol.

This is safe after the parser has verified that `hashnum` is not negative. You may eventually want to validate that it also fits within `uint32_t`.

### `sizeof(message)`

```
sizeof(message)
```

Because `message` is an actual two-element array here:

```
sizeof(message) = 2 × sizeof(uint32_t)
                = 2 × 4
                = 8 bytes
```

Therefore:

```
send_all(socket_fd, message, sizeof(message))
```

sends all eight Initialization bytes.

## 5. `send_all`

```
int send_all(int socket_fd, const void *buffer, size_t length) {
    const unsigned char *next_byte = buffer;
    size_t bytes_remaining = length;

    while (bytes_remaining > 0) {
        ssize_t bytes_sent = send(
            socket_fd,
            next_byte,
            bytes_remaining,
            0
        );

        if (bytes_sent < 0) {
            perror("send");
            return 1;
        }

        if (bytes_sent == 0) {
            fprintf(stderr, "Connection closed while sending\n");
            return 1;
        }

        next_byte += bytes_sent;
        bytes_remaining -= (size_t)bytes_sent;
    }

    return 0;
}
```

This function exists because one `send()` call is not guaranteed to send everything you requested.

For example:

```
send(socket_fd, buffer, 1000, 0);
```

could return:

```
1000  // all bytes sent
600   // only the first 600 bytes accepted
100   // only the first 100 bytes accepted
-1    // error
```

If it sends only 600 bytes, your program must call `send()` again for the remaining 400.

### Generic buffer pointer

```
const void *buffer
```

`void *` means a generic memory address. It allows `send_all()` to accept many types of buffers:

```
uint32_t message[2];
char text[100];
unsigned char payload[4096];
```

`const` means `send_all()` promises not to modify the buffer.

### Why convert it to `unsigned char *`?

```
const unsigned char *next_byte = buffer;
```

Pointer arithmetic on `void *` is not standard C because `void` has no size. The compiler does not know what “move forward by one `void`” means.

An `unsigned char` is exactly one byte, so:

```
next_byte += 5;
```

means “move forward five bytes.”

### `size_t`

```
size_t bytes_remaining = length;
```

`size_t` is an unsigned integer type used for memory sizes and object lengths. `sizeof(...)` returns a `size_t`.

At first:

```
bytes_remaining = total message length
```

For Initialization:

```
bytes_remaining = 8
```

### The loop

```
while (bytes_remaining > 0)
```

The function keeps calling `send()` until every byte has been accepted or an error occurs.

Suppose the first call sends only three of eight bytes:

```
Before:
next_byte      → byte 0
bytes_remaining = 8

send returns 3

After:
next_byte      → byte 3
bytes_remaining = 5
```

These lines perform that update:

```
next_byte += bytes_sent;
bytes_remaining -= (size_t)bytes_sent;
```

The next `send()` starts at byte 3 instead of resending byte 0.

### `ssize_t`

```
ssize_t bytes_sent
```

`send()` needs to return either:

- A nonnegative number of bytes.
- `-1` for an error.

Because `size_t` cannot represent negative numbers, `send()` returns the signed size type `ssize_t`.

### Calling `send`

```
send(socket_fd, next_byte, bytes_remaining, 0)
```

Its arguments mean:

- Send through `socket_fd`.
- Start reading bytes at `next_byte`.
- Try to send `bytes_remaining` bytes.
- Use no special flags.

### A robustness improvement

A signal can interrupt `send()`, setting `errno` to `EINTR`. A more robust version retries that case:

```
#include <errno.h>
```

```
if (bytes_sent < 0) {
    if (errno == EINTR) {
        continue;
    }

    perror("send");
    return 1;
}
```

This is worth adding eventually, although understanding the basic loop comes first.

## 6. `close`

```
close(socket_fd);
```

`close()` tells the operating system you are finished with the socket descriptor.

It does not free `args.filename`; those are unrelated resources:

```
close(socket_fd);   // socket resource
free(args.filename); // dynamically allocated memory
```

---

## 7. `free`

```
free(args.filename);
```

Your parser used `malloc()` to create a copy of the filename:

```
args->filename = malloc(len + 1);
```

That memory remains allocated until you call `free()`.

After freeing it, do not use:

```
args.filename
```

unless you assign it new valid memory. The pointer’s old address no longer belongs to your program.

---

The most important conceptual distinction is:

```
connect_to_server()
    establishes the TCP connection

run_client_protocol()
    performs your assignment’s message exchange

send_initialization()
    understands the Initialization message format

send_all()
    understands how to reliably send raw bytes over TCP
```

That structure keeps each layer understandable and makes failures easier to locate.
